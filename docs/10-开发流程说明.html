开发流程说明

1. 开发阶段划分

本项目开发分为3个阶段：

  1. Phase 1：需求分析与系统设计
  2. Phase 2：电表档案管理功能和随时抄表功能开发
  3. Phase 3：日志查询功能开发

2. Phase 1：需求分析与系统设计

2.1 需求分析文档编写

  • 任务内容：编写所有功能模块的需求分析文档
  • 文档内容：
    • 电表档案管理功能需求分析
    • 随时抄表功能需求分析
    • 日志查询功能需求分析
  • 文档要求：
    • 功能需求：详细描述每个功能点
    • 用户场景：描述典型用户使用场景
    • 验收标准：定义功能验收标准

2.2 概要设计文档编写

  • 任务内容：编写系统概要设计文档
  • 文档内容：
    • 系统架构设计文档
    • 数据库设计文档（表结构设计）
    • API接口设计文档
    • 部署架构设计文档
  • 文档要求：
    • 架构图：绘制系统架构图和模块划分图
    • 数据库设计：设计完整的表结构和索引
    • API接口设计：定义所有API接口规范

2.3 前端项目框架搭建

  • 任务内容：搭建Vue 3前端项目框架
  • 交付物：
    • 前端项目结构（src、public、package.json）
    • 基础布局组件（Layout、Navbar、Sidebar）
    • 路由配置（Vue Router）
    • 状态管理配置（Pinia）
    • HTTP请求封装（Axios拦截器）

2.4 后端项目框架搭建

  • 任务内容：搭建Web BackEnd、UCI、Channels、DLMS模拟表服务四个Spring Boot项目框架
  • 交付物：
    • Spring Boot项目结构（pom.xml、src/main/java、src/main/resources）
    • 数据库配置（application.yml）
    • MyBatis配置
    • REST API基础框架（Controller、Service、Dao）
    • 统一返回结果封装
    • 统一异常处理

2.5 Common组件开发

  • 任务内容：开发Common模块的4个公共组件
  • 交付物：
    • MQBus组件（消息队列通信封装，供UCI和Channels使用）
    • Protocol组件（DLMS协议编解码，供UCI和模拟表使用）
    • Logger组件（日志记录，供所有服务使用）
    • LoggerQuery组件（日志查询，供Web BackEnd使用）
  • 详细设计：参考《06-Common模块开发指导》

3. Phase 2：电表档案管理功能和随时抄表功能开发

3.1 详细设计文档编写

  • 任务内容：编写电表档案管理和随时抄表功能的详细设计文档
  • 文档内容：
    • 电表档案管理功能详细设计文档
    • 随时抄表功能详细设计文档

3.2 前端界面开发

  • 任务内容：开发电表档案管理和随时抄表操作Vue界面
  • 功能模块：
    • 电表档案管理界面：电表列表、详情、增删改查、批量导入导出
    • 随时抄表操作界面：电表选择、抄读数据项选择、抄读参数配置、抄读任务触发、抄读结果实时展示

3.3 Web BackEnd服务开发

  • 任务内容：开发电表档案管理和随时抄表操作REST API
  • 功能模块：
    • 电表档案管理API：电表列表查询、详情查询、增删改查、批量导入导出
    • 随时抄表操作API：抄读任务触发API、抄读结果实时返回

3.4 UCI服务开发

  • 任务内容：开发UCI随时抄表接口服务
  • 功能模块：
    • 随时抄表接口定义（REST API）
    • 任务分解与并发控制（按电表分解任务，同电表数据项串行抄读、多电表并行执行）
    • 电表档案读取（从数据库读取电表地址、LLS认证密码）
    • DLMS报文组包（ASN.1编码）和解包（ASN.1解码）
    • MQBus消息队列发送（发送任务到Channels服务）和监听（接收返回结果）
    • 消息格式参考《06-Common模块开发指导》

3.5 Channels服务开发

  • 任务内容：开发Channels通信服务
  • 功能模块：
    • TCP服务器模式（监听端口，接收电表连接）
    • 登录报文处理（解析电表地址，建立身份映射）
    • 心跳报文处理（更新心跳时间，9分钟超时判断（3个心跳周期））
    • AARQ报文组装（含LLS认证信息）和AARQ/AARE应用连接建立
    • 根据电表地址查找连接，透明转发DLMS报文
    • 通过MQBus接收UCI任务、返回响应

3.6 DLMS模拟表服务开发

  • 任务内容：开发DLMS模拟表服务用于测试
  • 功能模块：
    • 电表档案读取（从数据库读取电表地址、LLS认证密码等）
    • TCP客户端模式（主动连接Channels服务）
    • 登录报文发送（携带电表地址）
    • 心跳报文发送（3分钟间隔）
    • AARQ/AARE响应（含LLS认证密码验证）
    • DLMS GET请求响应（生成模拟数据）
    • 多电表实例模拟

4. Phase 3：日志查询功能开发

4.1 详细设计文档编写

  • 任务内容：编写日志查询功能的详细设计文档

4.2 前端界面开发

  • 任务内容：开发日志查询Vue界面
  • 功能模块：
    • 系统日志查询界面（时间范围、日志级别、关键词搜索）
    • 日志详情查看
    • 日志导出功能

4.3 后端API开发

  • 任务内容：开发日志查询REST API
  • 功能模块：
    • 系统日志查询API
    • 日志详情查询API
    • 日志导出API
  • 存储方式：系统日志基于文件存储（Logger组件）

5. 开发流程规范

5.1 每个阶段的流程

  1. 需求分析文档编写：明确功能需求和验收标准
  2. 概要设计文档编写：设计系统架构和模块划分
  3. 详细设计文档编写：设计类、方法、数据库表结构
  4. 编码实现：按照设计文档编写代码
  5. 单元测试：编写单元测试代码
  6. 集成测试：测试模块间集成和功能完整性

5.2 文档编写要求

  • 需求文档：详细描述功能需求、用户场景、验收标准
  • 概要设计文档：绘制架构图、模块划分、接口定义
  • 详细设计文档：设计类图、方法说明、数据库表结构

5.3 代码编写要求

  • 命名规范：遵循Java和Vue命名规范
  • 代码注释：关键逻辑添加注释
  • 单元测试：编写单元测试代码
