团队分工合作指导

1. 团队组织

1.1 组织方式

  • 团队规模：每组5人
  • 开发模式：每个小组独立完成所有模块，交付完整可运行系统
  • 模块覆盖：前端、后端、UCI服务、Channels服务、Common模块、DLMS模拟表服务

1.2 项目模块清单

序号 模块 技术栈
1 Web FrontEnd（前端） Vue 3 + Element Plus
2 Web BackEnd服务 Spring Boot
3 UCI服务 Spring Boot
4 Channels服务 Spring Boot
5 Common模块 MQBus、Protocol、Logger、LoggerQuery
6 DLMS模拟表服务 Spring Boot + MyBatis（TCP客户端）

2. 人员分工

2.1 分工总览

成员 角色 负责模块 Common组件
成员A 前端开发工程师 Web FrontEnd -
成员B 后端开发工程师 Web BackEnd服务、数据库设计 -
成员C 通信协议工程师 UCI服务 Protocol组件
成员D 通信服务工程师 Channels服务 MQBus组件
成员E 测试与日志工程师 DLMS模拟表服务 Logger组件、LoggerQuery组件

2.2 工作量平衡说明

  • 成员C：UCI服务负责DLMS报文组包/解包（ASN.1编解码），技术难度最高，仅分配Protocol组件
  • 成员D：Channels服务负责TCP通信、连接管理和AARQ认证，搭配MQBus组件和Protocol组件
  • 成员E：模拟表服务工作量相对较小，搭配Logger和LoggerQuery两个组件

3. 各成员职责详述

3.1 成员A：前端开发工程师

负责模块：Web FrontEnd

主要职责：

  • 系统界面开发（Vue 3 + Element Plus）
  • 电表档案管理界面（增删改查、批量导入导出）
  • 随时抄表界面（电表选择、数据项勾选、抄读结果实时展示）
  • 日志查询界面（系统日志查询）
  • 前后端API对接（调用Web BackEnd的REST API）

交付物：

  • 前端可运行应用
  • 与Web BackEnd API的对接完成

依赖：

  • 成员B提供REST API接口定义（参考《05-API接口规范》）

3.2 成员B：后端开发工程师

负责模块：Web BackEnd服务、数据库设计

主要职责：

  • 数据库设计与实现（参考《04-数据库设计规范》）
    • 电表资产表（asset_meter）
    • 数据项字典表（dict_data_item）
  • Web BackEnd服务开发（Spring Boot）
    • 电表档案管理API（增删改查、批量导入导出）
    • 随时抄表API（调用UCI服务）
    • 日志查询API（调用LoggerQuery组件）
  • 数据库初始化脚本（建表、初始化数据项字典）

交付物：

  • Web BackEnd可运行服务
  • 数据库建表和初始化脚本
  • REST API接口（供前端调用）

依赖：

  • 成员E提供LoggerQuery组件（用于日志查询API）
  • 成员C提供UCI服务接口（用于随时抄表API转发）

3.3 成员C：通信协议工程师

负责模块：UCI服务、Protocol组件

主要职责：

  • Protocol组件开发（参考《06-Common模块开发指导》第3节）
    • DLMS报文组包（ASN.1 BER编码）
    • DLMS报文解包（ASN.1 BER解码）
    • OBIS码管理、COSEM对象标识
    • GET请求/响应结构
  • UCI服务开发（Spring Boot）
    • 随时抄表接口服务
    • 电表档案管理（从数据库加载，含LLS认证密码）
    • 数据项管理（从数据库加载）
    • 任务分解与并发控制（按电表分解任务，同电表数据项串行抄读、多电表并行执行）
    • 通过MQBus与Channels服务通信（发送任务、接收结果）

交付物：

  • Protocol组件JAR包（供成员D的Channels服务和成员E的模拟表服务使用）
  • UCI服务可运行服务

依赖：

  • 成员D提供MQBus组件JAR包
  • 成员B提供数据库表结构（电表档案、数据项字典）

3.4 成员D：通信服务工程师

负责模块：Channels服务、MQBus组件

主要职责：

  • MQBus组件开发（参考《06-Common模块开发指导》第2节）
    • ActiveMQ连接管理
    • 消息发送和接收
    • MQMessage消息封装
    • 消息队列监听
  • Channels服务开发（Spring Boot）
    • TCP服务器模式（监听端口，接收电表连接）
    • 登录报文处理（解析电表地址，建立身份映射）
    • 心跳报文处理（更新心跳时间，9分钟超时判断（3个心跳周期））
    • 电表地址映射管理（电表地址→TCP连接）
    • AARQ报文组装（含LLS认证信息）和AARQ/AARE应用连接建立
    • 根据电表地址查找连接，转发DLMS报文
    • 通过MQBus接收UCI任务、返回响应

交付物：

  • MQBus组件JAR包（供成员C的UCI服务使用）
  • Channels服务可运行服务

依赖：

  • 成员C提供Protocol组件JAR包（用于AARQ报文组装）

3.5 成员E：测试与日志工程师

负责模块：DLMS模拟表服务、Logger组件、LoggerQuery组件

主要职责：

  • Logger组件开发（参考《06-Common模块开发指导》第4节）
    • 基于Lucene的日志索引和存储
    • 文件日志输出、控制台日志输出
    • 日志级别管理（info、warn、error、debug）
  • LoggerQuery组件开发（参考《06-Common模块开发指导》第5节）
    • 基于Lucene的日志索引查询
    • 时间范围查询、日志级别筛选、关键词搜索
  • DLMS模拟表服务开发（参考《08-DLMS模拟表服务设计》）
    • 电表档案读取（从数据库读取电表地址、LLS认证密码等）
    • TCP客户端模式（主动连接Channels服务）
    • 登录报文发送（携带电表地址）
    • 心跳报文发送（3分钟间隔）
    • AARQ/AARE响应（含LLS认证密码验证）
    • DLMS GET请求响应（生成模拟数据）
    • 多电表实例模拟

交付物：

  • Logger组件JAR包（供所有服务使用）
  • LoggerQuery组件JAR包（供成员B的Web BackEnd使用）
  • DLMS模拟表服务可运行服务

依赖：

  • 成员C提供Protocol组件JAR包（用于DLMS报文解析和响应构建）
  • 成员B提供数据库表结构（电表档案，用于读取电表地址和LLS认证密码）

4. Common组件归属与依赖

4.1 组件开发归属

组件 开发者 使用者
MQBus组件 成员D UCI服务、Channels服务
Protocol组件 成员C UCI服务、Channels服务、DLMS模拟表服务
Logger组件 成员E 所有服务
LoggerQuery组件 成员E Web BackEnd服务

4.2 组件交付顺序

Common组件是其他服务的基础，需优先开发并交付JAR包：

第一阶段：Common组件开发
  成员D → MQBus.jar
  成员C → Protocol.jar
  成员E → Logger.jar、LoggerQuery.jar

第二阶段：服务开发（集成Common组件）
  成员A → 前端（不依赖Common组件）
  成员B → Web BackEnd（集成LoggerQuery.jar）
  成员C → UCI服务（集成MQBus.jar、Protocol.jar）
  成员D → Channels服务（集成MQBus.jar、Protocol.jar）
  成员E → 模拟表服务（集成Protocol.jar、Logger.jar）

4.3 接口约定

各成员开发前需共同确认以下接口约定：

  • MQMessage消息格式：由成员D定义，参考《06-Common模块开发指导》第2.2节
  • REST API接口：由成员B定义，参考《05-API接口规范》
  • 数据库表结构：由成员B定义，参考《04-数据库设计规范》

5. 协作机制

5.1 依赖关系图 

成员A（前端）──依赖──→ 成员B（Web BackEnd API）
成员B（Web BackEnd）──依赖──→ 成员C（UCI服务接口）
成员B（Web BackEnd）──依赖──→ 成员E（LoggerQuery组件）
成员C（UCI服务）──依赖──→ 成员D（MQBus组件）
成员C（UCI服务）──依赖──→ 成员B（数据库表结构）
成员D（Channels服务）──依赖──→ 成员C（Protocol组件）
成员E（模拟表服务）──依赖──→ 成员C（Protocol组件）
成员E（模拟表服务）──依赖──→ 成员B（数据库表结构）
成员E（模拟表服务）──依赖──→ 成员D（Channels服务地址）

5.2 协作要点

协作事项 负责人 配合人 时间节点
MQMessage消息格式定义 成员D 成员C 开发前确认
REST API接口定义 成员B 成员A 开发前确认
数据库表结构确认 成员B 成员C、成员E 开发前确认
MQBus.jar交付 成员D 成员C 第一阶段结束
Protocol.jar交付 成员C 成员D、成员E 第一阶段结束
Logger.jar交付 成员E 全员 第一阶段结束
LoggerQuery.jar交付 成员E 成员B 第一阶段结束

5.3 沟通机制

  • 每日同步：简短同步开发进度和阻塞问题
  • 接口变更：任何接口变更需及时通知相关成员
  • 联调准备：第二阶段结束前完成各服务独立测试

6. 开发计划

6.1 开发迭代划分

迭代 内容 成员 周期
迭代1 需求分析与系统设计 全员 1周
迭代2 Common组件开发与交付 C、D、E 1.5周
迭代3 各服务独立开发 全员 3周
迭代4 集成联调与测试 全员 1周
迭代5 缺陷修复与交付 全员 0.5周

6.2 各迭代成员任务

迭代1：需求分析与系统设计（全员参与）

  • 共同确认系统架构（参考《02-系统架构设计》）
  • 共同确认数据库表结构（成员B牵头）
  • 共同确认REST API接口（成员B牵头）
  • 共同确认MQMessage消息格式（成员D牵头）
  • 编写各模块详细设计文档

迭代2：Common组件开发与交付（成员C、D、E）

  • 成员C：开发Protocol组件，交付Protocol.jar
  • 成员D：开发MQBus组件，交付MQBus.jar
  • 成员E：开发Logger和LoggerQuery组件，交付JAR包
  • 成员A、B：并行开发前端和后端基础框架

迭代3：各服务独立开发（全员）

  • 成员A：前端界面开发
  • 成员B：Web BackEnd服务和数据库实现
  • 成员C：UCI服务开发（集成MQBus.jar、Protocol.jar）
  • 成员D：Channels服务开发（集成MQBus.jar、Protocol.jar）
  • 成员E：DLMS模拟表服务开发（集成Protocol.jar、Logger.jar）

迭代4：集成联调与测试（全员参与）

  • 启动所有服务（Web BackEnd、UCI、Channels、DLMS模拟表）
  • 端到端联调：前端→Web BackEnd→UCI→Channels→模拟表
  • 验证随时抄表完整流程
  • 验证电表档案管理功能
  • 验证日志查询功能

迭代5：缺陷修复与交付（全员参与）

  • 修复联调发现的问题
  • 完善文档
  • 最终验收准备

6.3 里程碑

里程碑 内容 验收标准
M1 设计完成 架构、数据库、API、消息格式确认
M2 Common组件交付 4个组件JAR包交付，单元测试通过
M3 各服务独立可运行 各服务能独立启动，通过单元测试
M4 集成联调通过 端到端随时抄表流程跑通
M5 系统交付 所有功能验证通过，文档齐全

7. 联调测试

7.1 测试环境准备

服务 启动顺序 端口
MySQL数据库 1 3306
ActiveMQ 2 61616
Channels服务 3 9999（TCP监听）
DLMS模拟表服务 4 主动连接Channels:9999
UCI服务 5 8081
Web BackEnd服务 6 8080
Web FrontEnd 7 80

7.2 端到端测试场景

随时抄表完整流程：

  1. 启动所有服务
  2. 验证模拟表成功连接Channels服务（登录报文、心跳报文）
  3. 前端选择电表和数据项，触发随时抄表
  4. 验证数据流：前端→Web BackEnd→UCI→MQBus→Channels→模拟表→返回
  5. 验证前端实时展示抄读结果

电表档案管理：

  1. 前端新增电表档案
  2. 验证数据库保存成功
  3. 前端查询、修改、删除电表档案

日志查询：

  1. 执行各项操作产生日志
  2. 前端查询系统日志
  3. 验证日志按时间和级别筛选

8. 风险控制

风险 影响 应对措施
DLMS ASN.1编解码难度高 成员C进度延迟 迭代1优先攻关，参考DLMS标准
Common组件交付延迟 阻塞服务开发 迭代2优先完成，成员A/B并行开发基础框架
接口定义变更 影响多个成员 迭代1充分确认，变更需通知全员
联调问题多 迭代4时间不足 各服务迭代3完成独立测试，减少联调问题
