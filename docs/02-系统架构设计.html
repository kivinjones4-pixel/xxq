系统架构设计

1. 整体架构

HES二次开发项目采用前后端分离的微服务架构，所有服务均为自研，系统整体架构如下：

HES系统整体架构
├── FrontEnd层（前端）
│   └── Web FrontEnd - Vue 3前端应用
│       ├── 电表档案管理界面
│       ├── 随时抄表界面
│       └── 日志查询界面
│
├── BackEnd层（后端）
│   ├── Web BackEnd服务 - REST API服务
│   │   ├── 电表档案管理API
│   │   ├── 随时抄表API
│   │   └── 日志查询API
│   │
│   └── UCI服务 - 随时抄表接口服务
│       └── 随时抄表REST API接口
│       └── MQBus消息通信（与Channels交互）
│
├── 通信服务层（自研）
│   ├── Channels服务 - DLMS协议通信服务（自研）
│   │   └── DLMS协议实现
│   │   └── 电表通信管理
│   │   └── MQBus消息处理
│   │
│   └── DLMS模拟表服务 - DLMS电表模拟（自研）
│       └── 模拟DLMS电表设备
│       └── 作为TCP客户端连接Channels服务
│       └── 发送登录报文和心跳报文
│       └── 提供测试环境
│
└── 基础设施层
    ├── 数据库 - MySQL
    ├── 消息队列 - ActiveMQ
    └── Web服务器（前端静态资源）

2. 模块划分

2.1 FrontEnd模块

Web FrontEnd

  • 职责：用户界面展示和交互
  • 技术栈：Vue 3 + Element Plus + Pinia + Axios
  • 部署方式：静态资源部署到Web服务器
  • 通信方式：通过HTTP API与Web BackEnd服务通信

功能模块

  1. 电表档案管理模块：电表列表、详情、增删改查、批量导入导出
  2. 随时抄表模块：电表选择、抄读触发、结果展示
  3. 日志查询模块：系统日志查询

2.2 BackEnd模块

Web BackEnd服务

  • 职责：提供REST API接口，处理前端请求
  • 技术栈：Spring Boot + MyBatis + Maven
  • 部署方式：Spring Boot可执行JAR（独立Java进程）
  • 通信方式：
    • 通过HTTP API与前端通信
    • 通过HTTP调用UCI服务触发随时抄表

UCI服务

  • 职责：提供随时抄表接口服务，负责DLMS报文组包和解包
  • 技术栈：Spring Boot + MQBus（自研） + Maven
  • 部署方式：Spring Boot可执行JAR（独立Java进程）
  • 通信方式：
    • 通过HTTP API与Web BackEnd服务通信
    • 通过MQBus消息队列与Channels服务通信
  • 核心功能：
    • 组包功能：组织DLMS请求报文（ASN.1编码）
    • 解包功能：解析DLMS响应报文（ASN.1解码）
    • 电表档案管理：从数据库加载电表信息（电表地址、LLS认证密码等）
    • 数据项管理：从数据库加载数据项定义（OBIS码、数据类型等）
    • 任务分解：将前端提交的多电表多数据项抄读请求按电表维度分解为独立任务（一个电表一个抄读任务）
    • 并发控制：同一电表任务内数据项串行抄读（上一个数据项完成后才抄读下一个），不同电表任务并行执行
    • REST API：提供随时抄表接口
    • MQBus通信：发送任务消息到Channels，接收响应消息

2.3 Common模块（公共组件）

Common模块提供基础设施功能供各服务使用，包含4个自研组件：

组件 职责 使用者
MQBus组件 消息队列通信封装（封装ActiveMQ），用于服务间异步通信 UCI服务、Channels服务
Protocol组件 DLMS协议解析（ASN.1 BER编解码、OBIS码管理、AARQ/AARE应用连接含LLS认证、GET请求/响应结构） UCI服务、Channels服务、DLMS模拟表服务
Logger组件 分布式日志记录（基于Lucene），文件日志输出 所有服务
LoggerQuery组件 日志查询（配合Logger组件使用），支持时间范围、级别筛选、关键词搜索 Web BackEnd服务

详细设计：详见《06-Common模块开发指导》

2.4 通信服务模块（自研）

Channels服务

  • 职责：负责TCP/IP通信、AARQ/AARE应用连接和消息转发
  • 技术栈：Spring Boot + MQBus组件（自研） + Maven
  • 部署方式：独立Java进程（Windows服务）
  • 通信方式：
    • 通过MQBus消息队列与UCI服务通信（接收DLMS报文，转发电表响应）
    • 作为TCP服务器监听端口，等待电表（真实电表或模拟表）作为TCP客户端主动连接
  • 核心功能：
    • 监听电表连接：作为TCP服务器，监听指定端口，等待电表（真实电表或模拟表）作为TCP客户端主动连接（TCP常连接）
    • 接收登录报文：接收电表发送的登录报文，解析电表地址，建立电表身份映射
    • 接收心跳报文：接收电表发送的心跳报文，更新最后心跳时间，判断心跳超时（9分钟，3个心跳周期）
    • 应用连接建立：组装AARQ报文（含LLS认证信息），执行AARQ/AARE应用连接建立流程
    • 会话管理：管理电表会话的建立、维护和断开
    • 连接池管理：管理多个电表连接和并发通信
    • 报文转发：透明转发DLMS报文
    • MQBus通信：接收UCI任务消息，发送响应消息
    • 电表在线状态管理：记录和管理电表在线状态

DLMS模拟表服务

  • 职责：模拟DLMS电表设备，作为TCP客户端主动连接Channels服务
  • 技术栈：Spring Boot + MyBatis + Maven
  • 部署方式：独立Java进程
  • 通信方式：作为TCP客户端（模拟电表角色），主动连接Channels服务
  • 核心功能：
    • 读取电表档案：从数据库读取电表档案（电表地址、LLS认证密码等），用于身份识别和认证验证
    • 主动连接Channels服务：作为TCP客户端，主动连接Channels服务的监听端口
    • 发送登录报文：连接成功后发送登录报文，携带电表地址进行身份识别
    • 发送心跳报文：定期发送心跳报文，保持连接活跃
    • LLS认证验证：接收AARQ后验证LLS认证密码，返回AARE确认应用连接
    • 响应DLMS请求：响应Channels服务发送的DLMS GET请求

3.3 UCI服务与Channels服务通信（自研） 

UCI与Channels通信架构
┌─────────────┐
│    UCI      │
│   服务      │
│             │
│ - MQBus组件 │（自研）
└─────────────┘
      │
      ├─→ MQBus消息队列 ─→ ┌─────────────┐
      │  (发送抄读任务)    │  Channels   │
      │                    │   服务      │（自研）
      │                    │             │
      │                    │ - DLMS通信  │（自研）
      │                    │ - 电表抄读  │
      │  (接收抄读结果)    └─────────────┘
      └─→ MQBus消息队列 ←─┘

通信方式：MQBus消息队列（ActiveMQ，自研组件）
消息队列名称：

  • 任务队列：HES.Task.Channels（UCI发送抄读任务到Channels）
  • 结果队列：HES.Result.UCI（Channels返回抄读结果给UCI）

关键特性：UCI服务与Channels服务均为自研，可根据需求调整消息格式

3.4 Channels服务与DLMS模拟表服务通信 

Channels与DLMS模拟表通信架构
┌─────────────┐
│  Channels   │
│   服务      │（自研）
│             │
│ - TCP服务器 │（监听端口）
│ - 接收登录报文│
│ - 接收心跳报文│
└─────────────┘
      │
      ↑ DLMS协议（TCP/IP）
      ↑
┌─────────────┐
│ DLMS模拟表  │
│   服务      │（自研）
│             │
│ - TCP客户端 │（主动连接）
│ - 发送登录报文│
│ - 发送心跳报文│
│ - 模拟电表  │
└─────────────┘

通信方式：DLMS协议（TCP/IP）
通信场景：

  • Channels服务作为TCP服务器，监听指定端口，等待DLMS模拟表服务连接
  • DLMS模拟表服务作为TCP客户端，主动连接Channels服务
  • 模拟表连接成功后，发送登录报文进行身份识别
  • 模拟表定期发送心跳报文，保持连接活跃
  • Channels服务接收登录和心跳报文，建立电表身份映射和连接状态管理

4. 数据流向

4.1 随时抄表数据流（DLMS模拟表） 

随时抄表数据流（DLMS模拟表）
1. DLMS模拟表服务 → Channels服务：作为TCP客户端，主动连接Channels服务
2. DLMS模拟表服务 → Channels服务：发送登录报文，携带电表地址进行身份识别
3. DLMS模拟表服务 → Channels服务：定期发送心跳报文，保持连接
4. 前端 → Web BackEnd服务：用户选择模拟电表、点击抄读按钮
5. Web BackEnd服务 → UCI服务：调用随时抄表API接口
6. UCI服务：读取电表档案（电表地址、LLS认证密码），组装DLMS GET报文
7. UCI服务 → MQBus消息队列：发送抄读任务消息（含电表地址、LLS认证密码、DLMS报文）
8. MQBus消息队列 → Channels服务：Channels接收任务消息
9. Channels服务 → DLMS模拟表服务：根据电表地址找到对应连接，组装AARQ报文（含LLS认证密码）并发送，建立应用连接
10. DLMS模拟表服务：验证LLS认证密码
11. DLMS模拟表服务 → Channels服务：返回AARE确认应用连接（含认证结果）
12. Channels服务 → DLMS模拟表服务：发送DLMS GET请求
13. DLMS模拟表服务 → Channels服务：返回模拟电表数据
14. Channels服务 → MQBus消息队列：返回抄读结果消息
15. MQBus消息队列 → UCI服务：UCI接收抄读结果消息
16. UCI服务 → Web BackEnd服务：返回抄读结果
17. Web BackEnd服务 → 前端：实时展示抄读结果数据

重要说明：随时抄表功能实时展示抄读数据。

6. 关键设计决策

决策 理由
前后端分离架构 现代化Web应用最佳实践，前后端独立开发和部署
微服务架构 BackEnd拆分为独立服务，职责清晰，易于维护和扩展
MQBus消息队列通信 UCI与Channels异步通信，解耦服务，提高可靠性（自研组件，可灵活调整消息格式）
全自研方案 掌握核心技术，便于维护和扩展（Channels服务、DLMS模拟表服务、Common模块）
Windows环境部署 符合项目运行环境要求
