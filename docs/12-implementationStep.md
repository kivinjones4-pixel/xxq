建议按“**先确定接口 → 跑通单表抄读 → 扩展业务 → 完整验收**”实施。不要等所有页面完成后才开始协议联调。

| 顺序 | 实施内容 | 完成标准 |
| --- | --- | --- |
| 1 | **明确关键合同**：协议字节格式、HTTP/MQ 字段、实时结果返回方式、超时重试规则 | 各模块输入输出明确，有请求与响应示例 |
| 2 | **搭建工程与环境**：Vue 前端、四个 Spring Boot 服务、Common、MySQL、ActiveMQ | 前端和四服务分别启动，数据库与 MQ 可连接 |
| 3 | **初始化数据库**：两张核心表、唯一索引、测试电表和数据项 | 至少有一个电表、一项可抄数据及 LLS 密码 |
| 4 | **实现 Protocol 最小子集**：登录、心跳、AARQ/AARE、单项 GET | 固定报文样本编解码验证通过 |
| 5 | **实现 Channels 与模拟表连接**：TCP、登录、心跳、地址映射 | 模拟表登录成功，心跳可维持连接，断线可清理 |
| 6 | **跑通认证与单项 GET** | Channels 完成 LLS 认证，从模拟表读取一个数据值 |
| 7 | **实现 MQBus**：任务与结果队列、消息关联 | 任务可发送，响应可准确关联原请求 |
| 8 | **实现 UCI 单表任务**：加载档案、构造 GET、发送任务、解析响应 | 调用 UCI 后，数据经 MQ 和模拟表完整返回 |
| 9 | **接通 Web BackEnd 与最小前端页面**：提交抄读、展示结果 | 网页点击后显示真实链路返回的模拟数据 |
| 10 | **扩展多表多项**：同任务串行、跨表并行、逐项结果状态 | 两个电表各读取三个数据项，结果不串表、不串项 |
| 11 | **补齐异常处理**：认证失败、超时、重连、重复/迟到消息、页面资源清理 | 失败有明确结果，任务不会无限等待或误报成功 |
| 12 | **完成档案管理**：增删改查、筛选、导入导出 | 页面、API、数据库一致，错误行可定位 |
| 13 | **完成日志功能**：Logger、LoggerQuery、查询页面与导出 | 能查询各服务产生的日志并定位抄读问题 |
| 14 | **整体验收与部署**：回归测试、覆盖率、Windows 启动说明 | 四服务独立运行，三大业务可演示，验收证据齐全 |

**两个贯穿全过程的事项：**

- 从工程搭建阶段就接入基础日志，完整的 Lucene 查询和日志页面可以后做。
- 每个功能或迭代先建立 `specs/编号-功能名/spec.md`，写清范围、验收场景和任务；实现并验证后再标记完成。

**第 9 步是第一个关键里程碑：网页 → 后端 → UCI → MQ → Channels → 模拟表 → 网页全部跑通。** 档案 CRUD 可以在数据库建好后并行开发，但不应阻塞这条核心链路。
