DLMS/COSEM over TCP/IP协议实现指导

1. 协议概述

1.1 协议名称

  • 协议名称：DLMS/COSEM over TCP/IP
  • 标准编号：IEC 62056-47（TCP/IP传输）、IEC 62056-6-2/6-3（DLMS/COSEM应用层）
  • 协议定位：智能电表通信的国际标准协议
  • 协议特点：本项目使用TCP/IP作为传输层

1.2 协议架构

层级 标准 说明
应用层 IEC 62056-6-2 COSEM对象模型
表示层 IEC 62056-6-3 ASN.1编码
传输层 IEC 62056-47 TCP/IP协议 ⭐ 本项目使用

2. 协议核心组件

2.1 DLMS协议核心

DLMS协议核心包括协议模块、协议头部处理和报文处理，具体类设计详见《06-Common模块开发指导》第3.2节。

2.2 ASN.1编解码

  • 编码功能：将数据编码为BER格式
  • 解码功能：将BER格式数据解码为应用数据

2.3 COSEM对象标识

  • OBIS码：6段式标识符，格式：A.B.C.D.E.F
  • 用途：唯一标识电表数据项

2.4 COSEM服务

服务 说明
GET 从设备读取数据（本项目主要使用）
SET 向设备写入数据
ACTION 执行设备操作

3.3 登录报文和心跳报文（DLMS模拟表服务）

除了标准的DLMS APDU报文，DLMS模拟表服务还需要发送登录报文和心跳报文，用于身份识别和连接保活。

3.3.1 登录报文

登录报文用于DLMS模拟表服务连接成功后，向Channels服务进行身份识别：

报文用途：

  • 电表身份识别：通过电表地址（表号）唯一标识电表
  • 连接建立确认：告知Channels服务当前连接的电表身份

报文格式：遵循DLMS Wrapper标准格式（详见3.2节），APDU字段为ASN.1编码的登录APDU。

登录APDU结构（ASN.1编码）：

登录APDU使用ASN.1 BER编码，包含以下字段：

字段 类型 说明
messageType INTEGER 报文类型，登录报文为0x01
meterAddress OCTET STRING 电表地址（电表表号），电表的唯一标识符
serialNumber OCTET STRING 电表序列号（可选）
meterType OCTET STRING 电表类型（可选）
timestamp OCTET STRING 报文发送时间戳

登录流程：

  1. DLMS模拟表服务作为TCP客户端，主动连接Channels服务
  2. 连接成功后，立即发送登录报文（Wrapper格式 + ASN.1编码的APDU）
  3. Channels服务解析登录报文，提取电表地址，记录电表地址与连接的映射关系
  4. Channels服务发送登录响应报文，确认登录成功
  5. 登录成功后，模拟电表进入心跳和请求处理状态

Channels登录响应报文：

Channels服务收到登录报文后，需要发送登录响应报文，报文遵循DLMS Wrapper标准格式（详见3.2节），APDU字段为ASN.1编码的登录响应APDU。

登录响应APDU结构（ASN.1编码）：

字段 类型 说明
messageType INTEGER 报文类型，登录响应为0x81
result INTEGER 登录结果（0=成功，非0=失败）
timestamp OCTET STRING 响应时间戳

报文类型编码扩展：

报文类型 messageType值 说明
LOGIN 0x01 登录请求
HEARTBEAT 0x02 心跳请求
LOGIN_RESPONSE 0x81 登录响应
HEARTBEAT_RESPONSE 0x82 心跳响应

TCP连接建立 Meter->>Channels: TCP连接请求 Channels-->>Meter: TCP连接确认 Note over Meter,Channels: 2. 发送登录报文 Meter->>Channels: 登录报文<br/>(Wrapper + ASN.1编码)<br/>包含: meterAddress, serialNumber, timestamp Note over Channels: 3. 3.3.2 心跳报文

心跳报文用于DLMS模拟表服务定期告知Channels服务电表仍然在线：

报文用途：

  • 连接保活：告知Channels服务电表仍然在线
  • 连接状态检测：Channels服务通过心跳超时判断电表是否离线

报文格式：遵循DLMS Wrapper标准格式（详见3.2节），APDU字段为ASN.1编码的心跳APDU。

心跳APDU结构（ASN.1编码）：

心跳APDU使用ASN.1 BER编码，包含以下字段：

字段 类型 说明
messageType INTEGER 报文类型，心跳报文为0x02
meterAddress OCTET STRING 电表地址（电表表号），电表的唯一标识符
timestamp OCTET STRING 报文发送时间戳

心跳机制：

  • 发送间隔：每3分钟发送一次心跳报文
  • 超时判断：Channels服务超过9分钟（3个心跳周期）未收到心跳，判断为超时，置电表为离线状态，断开TCP连接
  • 重连机制：TCP连接断开后，模拟电表尝试重新连接Channels服务

Channels心跳响应报文：

Channels服务收到心跳报文后，需要发送心跳响应报文，报文遵循DLMS Wrapper标准格式（详见3.2节），APDU字段为ASN.1编码的心跳响应APDU。

心跳响应APDU结构（ASN.1编码）：

字段 类型 说明
messageType INTEGER 报文类型，心跳响应为0x82
result INTEGER 心跳结果（0=成功，非0=失败）
timestamp OCTET STRING 响应时间戳

心跳时序图：

3.4 AARQ/AARE应用连接建立

在DLMS协议中，进行数据读取前需要先建立应用连接（Application Association）：

3.4.1 AARQ（应用连接请求）

当Channels服务找到电表连接后，需要先发送AARQ建立应用连接：

字段 说明
protocolVersion 协议版本
applicationContextName 应用上下文名称
callingAPTitle 调用方AP标题
calledAPTitle 被调用方AP标题
authenticationId 认证类型（LLS=1，低级安全认证）
authenticationValue 认证密码（LLS模式下为明文密码，来自电表档案auth_password字段）

3.4.2 AARE（应用连接响应）

电表收到AARQ后，验证LLS认证密码，返回AARE确认应用连接建立：

字段 说明
protocolVersion 协议版本
applicationContextName 应用上下文名称
result 连接结果（0=成功，非0=认证失败）

LLS认证说明：电表收到AARQ后，将authenticationValue中的密码与自身存储的密码进行比对。密码一致则认证通过（result=0），不一致则认证失败（result=非0）。

3.4.3 应用连接流程

  1. UCI从电表档案读取认证密码，通过MQBus将认证密码和GET请求报文发送给Channels服务
  2. Channels服务组装AARQ报文（包含LLS认证信息，ASN.1编码）
  3. Channels服务发送AARQ给电表（如果当前会话尚未建立应用连接）
  4. 电表验证LLS认证密码，返回AARE（result=0表示认证成功）
  5. 应用连接建立后，Channels发送GET请求读取数据

3.5 GET请求/响应结构

GET请求

字段 说明
invokeId 请求ID
cosemObject COSEM对象描述符（包含classId、OBIS码）
attributeId 属性ID

GET响应

字段 说明

3.6 ASN.1编码要点

ASN.1使用BER（Basic Encoding Rules）编码，采用TLV结构：

组成 说明
Tag 数据类型标识（1字节）
Length 数据长度
Value 数据内容

常用Tag值：

  • 0x02：INTEGER（整数）
  • 0x05：NULL（空值）
  • 0x30：SEQUENCE（序列）
  • 0x04：OCTET STRING（字节数组）

4.3 常用OBIS码列表

4.3.1 OBIS码格式说明

OBIS码（Object Identification System）是DLMS/COSEM协议中用于唯一标识电表数据项的编码系统，格式为 A.B.C.D.E.F：

字段 名称 说明
A 介质类型 0=抽象对象, 1=电表, 7=气表, 8=水表, 9=热表
B 通道号 0=总计, 1=A相, 2=B相, 3=C相, 4=零序, 12=AB线, 23=BC线, 31=CA线
C 测量值类型 见测量值类型表
D 测量值子类型 子类型或费率信息
E 费率 0=总, 1=尖, 2=峰, 3=平, 4=谷
F 数据类型 255=值, 254=最大值, 253=最小值

数据项ID（data_item_id）：

由于同一个OBIS码可能对应不同的COSEM类ID和属性ID（如需量值和需量时间戳共用OBIS码 1.0.1.6.0.255，但类ID和属性ID不同），数据项ID采用 OBIS码_classId_attributeId 组合格式保证唯一性：

示例 说明
1.0.1.8.0.255_3_2 正向有功总电能（OBIS=1.0.1.8.0.255, 类ID=3, 属性ID=2）
1.0.1.6.0.255_5_3 正向有功最大需量时间（OBIS=1.0.1.6.0.255, 类ID=5, 属性ID=3）

常用测量值类型（C字段）：

C值 测量值类型 说明
1 有功功率 瞬时有功功率
3 无功功率 瞬时无功功率
6 最大需量 需量周期内最大功率
8 电能 累计电能值
13 功率因数 瞬时功率因数

5. 协议实现框架

5.1 随时抄表协议流程

任务分解与并发执行规则：

  • 前端可同时选择多个电表和多个数据项，UCI将请求按电表维度分解为独立任务（一个电表一个抄读任务）
  • 同一电表任务内，多个数据项串行执行（上一个数据项抄读完成后才能抄读下一个）
  • 不同电表的任务并行执行

以下为单个电表任务内单个数据项的抄读流程：

  1. 应用层：Web BackEnd接收随时抄表请求，用户勾选多个电表和多个数据项
  2. UCI服务：⭐ UCI负责任务分解和组包
    • 将请求按电表维度分解为独立任务（一个电表一个抄读任务）
    • 对每个电表任务，从数据库读取电表档案（电表地址、LLS认证密码等）
    • 从数据库读取数据项信息（OBIS码、COSEM类ID、属性ID等）
    • 按数据项顺序组织DLMS GET请求报文（ASN.1编码），逐项串行发送
    • 通过MQBus发送任务消息到Channels服务（包含电表地址、LLS认证密码、DLMS GET报文）
  3. Channels服务：⭐ Channels负责通信和认证
    • 接收MQBus消息，解析电表地址（meterAddress）和LLS认证密码
    • 根据电表地址查找对应的TCP连接
    • 组装AARQ报文（含LLS认证信息，ASN.1编码）
    • 发送AARQ报文建立应用连接（如果尚未建立）
    • 接收AARE确认应用连接（含LLS认证结果）
    • 发送DLMS GET请求报文
    • 接收电表响应报文
    • 通过MQBus转发响应消息给UCI服务
  4. UCI服务：⭐ UCI负责解包
    • 接收响应报文，ASN.1解码
    • 提取数据值，处理数据类型转换
    • 返回结果给Web BackEnd
  5. 应用层：展示抄读数据

6. 协议开发要点

6.1 架构原则

  • 保持代码结构清晰
  • 编写完整的单元测试和集成测试

6.2 OBIS码管理

  • 使用dict_data_item字典表管理OBIS码
  • 根据DLMS标准初始化常用OBIS码

错误类型 说明
