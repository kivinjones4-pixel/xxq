HES项目概述

1. 项目背景

HES（Head-end System）智能电网用电信息采集系统是一个面向电力行业的用电信息采集和管理平台。本项目是基于现有HES系统的二次开发项目，目标是实现电表档案管理、随时抄表和日志查询等核心业务功能。

2. 项目目标

2.1 业务目标

  • 实现电表档案的增删改查和批量导入导出
  • 实现随时抄表操作（实时展示抄读数据）
  • 实现系统日志查询

2.2 技术目标

  • 采用Vue 3 + Element Plus构建前端界面
  • 采用Spring Boot构建后端服务
  • 实现Channels服务和Common模块
  • 实现DLMS模拟表服务用于测试
  • 实现前后端分离的现代化架构

3. 开发范围界定

3.1 自研开发功能

Web FrontEnd（前端）

  • 电表档案管理界面
  • 随时抄表界面
  • 日志查询界面

BackEnd（后端）

包括3个独立的Spring Boot服务：

  1. Web BackEnd服务

    • 电表档案管理API
    • 随时抄表API
    • 日志查询API

  2. UCI服务：随时抄表接口服务，负责DLMS报文组包/解包（ASN.1编解码），从数据库加载电表档案和数据项，通过MQBus与Channels服务通信（详见《02-系统架构设计》第2.2节）

  3. Channels服务：DLMS协议通信服务，作为TCP服务器监听电表连接（真实电表或模拟表均作为TCP客户端主动连接），处理登录/心跳报文，执行AARQ/AARE应用连接建立，管理电表会话，通过MQBus接收UCI任务并透明转发DLMS报文（详见《02-系统架构设计》第2.4节）

Common模块（公共组件）

实现以下组件：

  • MQBus组件：消息队列通信封装（封装ActiveMQ，用于服务间异步通信）
  • Protocol组件：DLMS协议解析（核心组件，必须自研）
  • Logger组件：分布式日志记录（基于Lucene实现）
  • LoggerQuery组件：日志查询（配合Logger组件使用）

DLMS模拟表服务

  • 模拟DLMS电表设备
  • 作为客户端连接到Channels服务
  • 提供DLMS协议响应
  • 用于项目测试和验证随时抄表功能

4. 运行环境

  • 操作系统：Windows Server 2016+
  • 数据库：MySQL 5.7或8.0
  • 消息队列：ActiveMQ 5.x
  • Java环境：JDK 1.8
  • 前端环境：Node.js 16.x或18.x

5. 项目特点

  • 全自研：前端、后端、Channels服务、Common模块、DLMS模拟表服务全部自行开发
  • 前后端分离：Vue 3前端 + Spring Boot后端微服务架构
  • 异步通信：通过MQBus消息队列实现UCI与Channels服务间异步通信
  • 标准协议：遵循DLMS/COSEM协议标准（IEC 62056）
  • 专注核心：聚焦电表档案管理、随时抄表、日志查询三大核心功能

6. 关键约束

6.1 开发约束

  • 根据业务需求自行设计实现
  • 遵循行业最佳实践和编码规范
  • 编写完整的单元测试和集成测试

6.2 架构约束

  • MQBus消息格式遵循标准定义（MQMessage类）
  • Channels服务架构遵循DLMS协议标准
  • Protocol组件架构遵循DLMS/COSEM协议标准

6.3 部署约束

  • 所有服务在Windows环境下运行
  • 使用Spring Boot可执行JAR部署
  • 通过Windows服务或批处理脚本启动服务
