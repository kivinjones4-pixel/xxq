# HES 基线提案

状态：依据现有 HTML 建立的需求基线；实现待开始。来源：文档 00 §2–5、01 §1–6、10 §1–4。

## Why：业务问题

电表档案、即时数据采集和运行日志需要统一管理。五人实训小组需独立交付完整系统，通过自研协议和模拟表验证实际抄读链路，不能仅用页面静态数据演示替代通信。

## What Changes：交付内容

| 能力 | 改动 | 规范 |
| --- | --- | --- |
| F1 电表档案 | 分页筛选、详情、增删改、Excel/CSV 导入导出 | REQ-METER-01、REQ-METER-02 |
| F2 随时抄表 | 多表多项选择、按表拆分、串并行控制、实时结果 | REQ-READ-01、REQ-READ-02 |
| F3 系统日志 | 文件和 Lucene 存储、查询、详情、导出 | REQ-LOG-01 |
| 通信支撑 | TCP 登录/心跳、LLS 应用连接、GET 编解码 | REQ-CONN-01、REQ-AUTH-01、REQ-PROTO-01 |
| 工程支撑 | 四个 Common 组件、数据库、MQBus、Windows 部署 | REQ-ARCH-01、REQ-DATA-01、REQ-MQ-01、REQ-DELIVERY-01 |

## 范围

开发六个模块及其测试、初始化 SQL、API 文档和部署说明。模拟表支持多实例、重连及不同类型的测试数据。优先完成真实进程间的随时抄表闭环。

本基线没有提出 SET/ACTION、定时抄表、计费、历史曲线、权限管理平台或额外业务表的交付要求；如需增加，另记变更目的与验收场景。

## 成功条件

- 文档 00 的 F1/F2/F3、A1–A4、P1–P7、D1–D3 有对应实现与验证。
- 四服务独立运行，模拟表经 LLS 认证成功抄读，页面显示真实链路返回的模拟数据。
- 三阶段依次交付：需求设计/骨架/Common，电表档案与随时抄表，日志查询。
- 按原任务书评分：功能 45、技术合规 35、代码质量 10、文档 5、运行联调 5；通过线 70。模拟表抄读或系统运行联调不通过直接不通过。F2 得分低于 15/25 或协议低于 9/15 触发原文降级规则。

## 影响与开放问题

接口、消息与数据库影响多个模块，修改时关联需求 ID、设计决策和任务。协议线格式、实时返回接口、错误与重试语义尚需细化，详见 [reference.md](reference.md)。本提案不将未定方案写成既定合同。
