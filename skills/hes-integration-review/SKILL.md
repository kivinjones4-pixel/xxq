# HES 联调与验收

先读仓库 `AGENTS.md`、`specs/spec.md` 和 `specs/task.md`；用 [验收检查表](references/checklist.md) 路由检查。必要时读 `docs/00-项目任务书.html` 核对评分规则。

## 执行

1. 识别是文档评审、代码评审还是实际运行验收；仅存在文档时输出实现缺口，不能报告测试通过。
2. 从实际构建配置读取命令和运行参数，确认数据库、消息队列、日志目录及测试数据。运行范围遵循用户授权，不自行删除共享数据或部署到其他环境。
3. 对照需求 ID 核查模块边界、API、数据库和协议职责。对 Q-01 等未决合同记录影响，避免猜测标准线格式。
4. 在授权测试环境执行正常链路与失败场景；只运行与当前改动有关的检查，最终完整验收才覆盖全链路。
5. 记录实际结果、证据路径、失败原因和复现步骤。关联的实现与验证均完成才更新任务勾选。

## 输出

按“需求/场景、通过/失败/未运行、证据、问题与后续任务”列出结果。将文档符合、代码符合、运行通过区分开。日志与报告隐藏认证密码；模拟表与系统完整运行未通过时，明确原任务书的一票否决影响。
