# HES 前端 CR

## 规范入口

先读 [AGENTS.md](../../AGENTS.md) 与 [前端代码开发与审查规范](./references/frontend-cr.md)。规范为唯一审查规则来源，按改动阅读 FE-01–FE-09 的相关章节，不在技能中复制规则。
涉及业务时读 [spec.md](../../specs/spec.md) 中关联需求；遇到未确定接口与语义时查 [reference.md](../../specs/reference.md)，将待决项与代码缺陷分开。

## 审查流程

1. 确定用户指定的文件、工作区差异、提交或 PR 范围。未指定时先检查工作区改动；没有可审代码时报告现状并请求具体目标，不虚构审查通过。
2. 读取差异及必要组件、store、API 封装、调用方和测试上下文。先确认实际技术版本与构建脚本，再判断行为。
3. 对照规范检查响应式状态、异步竞争、任务归属、数据项身份、错误展示、资源清理、敏感信息、样式与可访问性；仅追踪受本次改动影响的路径。
4. 通过现有检查或针对性的复现验证疑点；根据改动使用现有测试和构建工具，不为 CR 新建无实际价值的扫描脚本。环境缺失则记录未运行及其影响。
5. 按 FE-09 输出有证据的问题；单纯请求审查时不修改代码，用户已要求修复则在授权范围完成修复并验证，不重复索要许可。

## 输出约定

- 先列可操作发现，按 P0–P3 排序；每项给出准确文件/行号、触发条件、影响、规范条款和最小修复方向。
- 不把未经核实的疑点列为确定缺陷，不把既有问题归因于本次改动，不用个人风格偏好阻断交付。
- 随后说明检查范围、实际执行结果、未运行项及待决事项；未发现可操作问题时明确说明，不声称全系统无缺陷。
- 对仓库文件提供可定位链接；没有实现代码时仅可给规范层面的准备情况，不勾选开发任务或报告运行通过。
