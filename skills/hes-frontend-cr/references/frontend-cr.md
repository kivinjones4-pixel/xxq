# 前端代码开发与审查规范

适用范围：HES Web FrontEnd 的 Vue 页面、组件、状态管理、API 调用、样式和前端构建配置。本文是项目开发与 CR（Code Review）约定，不是原始 HTML 验收条款。业务行为以 [spec.md](../../../specs/spec.md) 为准，选型以 [AGENTS.md](../../../AGENTS.md) 中当前约定为准；未定业务规则见 [reference.md](../../../specs/reference.md)。

## FE-01 技术与工程边界

- 使用 Vue 3 Composition API、TS、Vite、Element Plus、Tailwind、Pinia、Vue Router、Axios；采用工程实际锁定版本，不将 `latest` 当成可复现版本。
- 当前尚无前端工程。创建时记录 Node 与依赖兼容性，提交锁文件；JavaScript/TypeScript 沿用工程决定，不为单次 CR 擅自迁移语言或升级依赖。
- 建议按 views（页面）、components（复用组件）、composables（有状态逻辑）、api（请求与 DTO 映射）、stores（跨页面状态）、router、styles 划分；目录以实际项目为准，不为形式创建空抽象。
- 页面负责交互编排，API 模块负责通信；组件不直接承担 DLMS 编解码、LLS 校验或后端任务调度。

## FE-02 组件与响应式状态

- 组件职责明确，重复且稳定的交互再抽取；Props 作为输入，变化通过事件或明确的状态接口传递，不隐式修改父组件数据。
- 派生值用计算状态表达，副作用放在明确的事件或监听中；避免同一数据在组件与 store 多处保存而失去同步。
- Pinia 用于确需共享或跨页面保留的状态，弹窗开关、局部表单等默认留在页面/组件内。
- 列表使用稳定业务标识作为 key；电表使用 ID，数据项使用完整 dataItemId，不单独以 OBIS 作为唯一键。
- 页面离开、组件卸载或任务切换时清理定时器、订阅和事件监听；异步结果必须验证仍属于当前页面/任务。

## FE-03 API、错误与请求竞争

- 页面通过统一 API 层访问 Web BackEnd；不得直接访问 UCI、Channels、数据库或 MQ。路径与请求方法遵循文档 05 和 REQ-API-01。
- 区分网络/HTTP 失败与 JSON 业务失败；普通响应按 code/message/data 解包，分页按 total/list；错误反馈明确且避免拦截器与页面重复提示。
- 筛选、翻页或路由变化触发新查询时，取消旧请求或使用请求序号防止迟到响应覆盖新结果；loading 状态也需归属正确请求。
- 写操作进行中阻止重复提交并在完成后恢复；不自动重试新增、导入、抄表等可能重复产生业务效果的请求。
- 文件导出独立处理二进制流与错误响应，不能把 JSON 错误保存成 Excel；使用临时下载 URL 时释放资源。
- 不编造未定义的字段或结果接口。实时通路、超时/重试单位等须先解决相关 Q 项，再实现调用。

## FE-04 档案、表单与导入导出

- 字段必填、长度、状态值与后端合同一致；前端校验改善交互，但不作为服务端校验的替代。
- 搜索条件变化后合理重置分页；删除末页最后一条记录后处理空页；刷新列表不意外丢失仍有效的筛选。
- 编辑时区分原值、修改值与未填写值，避免空字段误覆盖；保存成功后再关闭或刷新，失败保留用户可修正的输入。
- Excel/CSV 导入展示成功数、失败数和失败详情；不自行假设部分成功或全批回滚规则。
- 导出沿用当前筛选合同；当前页/全部匹配范围以 Q-06 的结论为准。禁用状态与离线状态分别展示。

## FE-05 随时抄表

- 用户可选多表多项；提交正确的电表 ID 和完整数据项 ID，不在前端按 OBIS 合并不同属性。
- UCI 承担同任务内串行/跨表并行；前端不通过发送多次 start 请求模拟后端任务分解。
- 任务 ID、选中对象和返回结果有明确归属；切换任务后不接收旧任务结果覆盖当前视图。
- 分别呈现等待、进行中、成功、失败及整体完成等已约定状态；收到任务 ID 不等于抄读成功，失败不显示为 0 或有效读数。
- 结果正确保留单位与精度；明确缩放由哪一层处理，防止前后端重复缩放。展示 0 时不误判为空。
- 按 Q-02 的正式合同实现结果获取、结束和断线行为；若使用轮询/流连接，任务结束与离开页面时停止资源占用。

## FE-06 样式与可访问性

- Element Plus 承担标准交互组件，Tailwind 组织布局和间距；共用颜色/间距约定，避免全局覆盖破坏其他页面。
- 保持 loading、空数据、错误、禁用状态可区分；表格长文本、窄窗口和弹窗内容不遮挡关键操作。
- 表单有可识别标签和错误信息，操作支持键盘访问与可见焦点；状态不能只靠颜色表达。
- 样式优先局部作用域或明确命名，不依赖深层选择器与任意强制覆盖堆叠解决布局问题。

## FE-07 数据展示与敏感信息

- 电表名称、日志、导入错误等外部文本默认以文本渲染；确需 HTML 时明确可信来源与净化处理，不能直接注入未可信内容。
- 认证密码不写入控制台、持久化 store、URL、错误上报或导出；密码字段的读取/回填策略遵循 Q-06。
- 前端构建配置中不放数据库、MQ 或其他服务秘密；浏览器中可见的配置不作为保密措施。
- 日志页时间范围、时区和边界与接口约定一致，详情与导出使用正确记录/筛选，不能串用旧查询结果。

## FE-08 验证与交付

从实际 package.json 和锁文件确定包管理器及可用命令。对受影响范围运行现有 lint、构建、类型检查（若配置）与相关测试；没有脚本或运行环境时写明未运行，不虚构命令和通过结果。

| 改动范围 | 优先验证场景 |
| --- | --- |
| 列表/表单 | 快速切换查询、空页、有效值 0、非法输入、提交失败、重复点击 |
| 导入导出 | 错误行与部分结果、筛选传递、二进制下载、JSON 错误响应 |
| 实时抄表 | 多表多项、相同 OBIS 不同属性、迟到结果、任务切换、失败状态、离开页面清理 |
| 样式/组件 | 正常/空/加载/错误状态，键盘、焦点、长内容与窄窗口 |

优先验证可观察行为及回归风险，不为静态文案或简单样式增加镜像实现测试。Mock 测试与真实联调证据分开报告；前端通过不代表四服务链路已通过。

## FE-09 CR 输出与严重程度

审查实际差异并读取必要调用方与上下文；用户未指定范围时优先工作区改动，无改动时明确待审目标。提出有具体触发条件、代码证据和用户影响的问题，不将偏好、待决业务规则或无关历史问题冒充本次缺陷。

| 级别 | 判断依据 |
| --- | --- |
| P0 | 已有证据表明会造成广泛严重事故，需立即处理；慎用 |
| P1 | 主要流程不可用、敏感信息泄露或明显数据错误，需优先修复 |
| P2 | 特定可复现场景下的功能、状态、资源或可访问性缺陷 |
| P3 | 有实际维护或体验影响但不紧急的问题；纯格式偏好交给工具 |

每个发现包含级别、文件和实际行号、触发条件、影响、对应 FE/REQ 条款与最小修复方向。按严重程度排序，合并同根因重复项；待核实事项单列。没有可操作问题时直接说明未发现问题，并列出验证范围与未运行项，不为凑数生成发现。
